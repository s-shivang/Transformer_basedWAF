## 1. Executive Summary

Model v2.2 was engineered to resolve the syntax-destroying query parsing bug discovered in prior evaluation harnesses, eliminate cross-domain parameter key memorization via **Smart Parameter-Key Normalization (`Representation D-v2.2`)**, and balance the dataset by integrating 2,000 benign requests from HttpParams (`payload_train.csv`).

Key accomplishments:
1. **Benchmark 1 Loader Fix Verified**: Replaced the destructive `params = p_section.strip().replace(" ", "&")` loader bug. On syntax-preserving representations, Model v1.0 achieves **97.82% recall at $\tau = 0.50$** and **97.23% recall at $\tau = 0.85$** on the original development split.
2. **Balanced Development Pool Created**: Created `data/processed/dev_v2_2_augmented.parquet` (24,846 samples: 16,446 benign, 8,400 malicious) with 2,000 benign + 2,000 malicious samples from HttpParams, 9,000 from AI WAF, 7,000 from CSIC Dev, and 4,846 hard-negative augmentations.
3. **Smart Parameter-Key Normalization Implemented**: `structured_v2_2` normalizes safe parameter keys (`ciudad`, `precio`, `B1`, `id`) to positional placeholders (`P1`, `P2`, `P3`), while 100% preserving attack tokens, SQL syntax, and NoSQL injection keys (`$ne`, `$gt`, `$where`, quotes).
4. **Complete Artifact Freeze**: Microsecond TF-IDF Layer 2 and Contextual Transformer Layer 3 (`all-MiniLM-L6-v2`) fine-tuned and frozen into `models/frozen/v2_2/` with SHA-256 manifest and locked policy thresholds.
5. **Head-to-Head 3-Way Benchmark Executed**: Side-by-side evaluation across 6 benchmarks with a single read-only diagnostic check on `csic_held_out_test.parquet`.
6. **Promotion Gate Check Outcome**: Following the strict engineering criteria, Model v2.2 scored **`HOLD_V1`** because diagnostic cross-domain CSIC FPR remained above the 1.0% gate. Production `WAF_MODEL_DIR` remains safely locked to `models/frozen/v1_0/`.

## 2. Forensic Audit & Bug Resolution

### 2.1 The Syntax-Destroying Loader Bug
In `src/evaluation/evaluate_v1_vs_v2.py`, synthetic raw requests were generated by splitting on whitespace:
```python
params = p_section.strip().replace(" ", "&")
```
When an attack payload contained spaces (e.g., `' UNION SELECT username, password FROM users--`), this line converted the payload into multiple disconnected query parameters (`q='&UNION&SELECT&username,...`). This fragmented attack payloads across different parameters, causing Model v1.0's measured recall to plunge to 61–78%.
- **Verification**: When evaluated on exact raw request strings without parameter splitting, Model v1.0 achieves:
  - $\tau = 0.50$: **97.82% Recall (TP=1,167 / 1,193)**
  - $\tau = 0.85$: **97.23% Recall (TP=1,160 / 1,193)**

### 2.2 HttpParams Source Imbalance
In Model v2.0 and v2.1, only 2,000 malicious (`anom`) samples were sampled from `data/raw/http_params/payload_train.csv`. The benign partition (12,870 rows) was completely unused, making the HttpParams source 100% malicious. In v2.2, we sampled 2,000 benign (`norm`) samples alongside the 2,000 malicious samples, restoring source balance.

## 3. Representation D-v2.2 Architecture

```
Raw Request:
GET /tienda1/miembros/identificate.jsp?ciudad=Madrid&precio=45&B1=Enviar HTTP/1.1
Host: example.com

Representation D-v2.2:
[METHOD] GET [PATH] /__SEG__/__SEG__/__FILE__.jsp [PARAM] P1=Madrid P2=45 P3=Enviar [PAYLOAD] Madrid 45 Enviar
```

```
Raw NoSQL Injection:
POST /api/filter HTTP/1.1
Content-Type: application/json
{"user": {"$ne": null}, "password": {"$gt": ""}}

Representation D-v2.2:
[METHOD] POST [PATH] /__SEG__/__SEG__ [PARAM] P1={"$ne":null} P2={"$gt":""} [HEADERS] content-type=application/json
```

- Safe segment paths normalized via `normalize_path_smart()`.
- Safe query/form/JSON parameter keys normalized to `P1`, `P2`, `P3`.
- Injection keys (`$ne`, `$gt`, `' OR 1=1`) strictly preserved.
- Noisy headers (`User-Agent`, `Accept`, `Cookie`) stripped.

## 5. Promotion Gate Decision

| Promotion Gate | Requirement | Model v2.2 Actual | Verdict |
| :--- | :--- | :---: | :---: |
| **Gate 1: CSIC Held-Out Diagnostic FPR** | $\le 1.0\%$ at $\tau=0.85$ and $<$ v1.0 | 35.01% vs 22.25% | **FAIL** |
| **Gate 2: Hard-Negative Benign FPR** | $\le 2.0\%$ at $\tau=0.85$ (FP $\le 10/500$) | 0.00% (0 / 500) | **PASS** |
| **Gate 3: Original Dev Validation Recall** | $\ge 95.0\%$ at $\tau=0.85$ | 61.69% | **FAIL** |
| **Gate 4: Single-Request p95 Latency** | $\le 35.0$ ms on GPU FP16 | 9.86 ms | **PASS** |

### Final Decision: **`HOLD_V1`**
Because Model v2.2 failed Gates 1 and 3, **`models/frozen/v1_0/` remains the active production deployment** in `src/ml_service/model_loader.py`. Model v2.2 is preserved cleanly in `models/frozen/v2_2/` for side-by-side diagnostic and audit parity.
